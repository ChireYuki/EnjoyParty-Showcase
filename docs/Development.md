# 测试与迭代

以下案例来自实际开发记录。它们说明如何从操作反馈定位问题，也说明哪些结论已经验证、哪些还没有。

## 案例一：隐藏界面后立即重新显示

突击门选择目标时，点击隐藏按钮没有达到预期效果。

原来的判断把“是否需要展示选择窗口”与“当前是否允许操作”混在一起：隐藏界面会禁止操作，刷新时就把它误判为已离开选择流程，随后恢复窗口。

修复把展示条件与操作许可分开。隐藏期间保留候选和已选目标，只关闭窗口可见性与交互；恢复后继续原来的选择。验证不仅检查按钮状态，还检查实际 UI 点击、持续刷新、取消与确认流程。

## 案例二：退房后新局仍是审判庭

进入审判庭后退出房间，在同一程序中重开图书馆，画面仍显示上一局的审判庭。

地图资源没变时，棋盘会复用已有对象；原退房清理只重置角色和演出队列，没有恢复已经被替换的环境。

修复在停止相关演出后恢复图书馆环境，并清空新任务界面的绑定缓存。验证覆盖真实本地 Host 断开、同图重开、新对局标识，以及普通图书馆退房不会重复重建环境。

## 案例三：一次买多张牌如何计数

商店增加批量购牌后，关卡中“累计获得卡牌”的任务不能把购买动作次数当成卡牌数量。

需要区分一次购买请求与其中实际获得的每一张牌，同时检查价格、售出状态和任务事件。这个案例体现的是功能之间的关联，不只是给商店多加一个按钮。
